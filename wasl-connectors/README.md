# أدوات وصل — حالة التنفيذ

هذه الأدوات **لم تُركب على الأجهزة ولم تُختبر على حساب واتساب أو هاتف حقيقي**. تكمل البروتوكول المحدد أدناه؛ خادم الاقتران مضاف في مشروع وصل على Convex، والنشر العام وارتباط الأجهزة والحسابات خطوات منفصلة تحتاج اختبارًا فعليًا. لا تعتبر تجميع الكود أو نجاح اختبارات الوحدات دليلًا على عمل التكاملات الحية.

## مسار الطلب الجديد

اللاندنج بيدج → Apps Script الموجود → الشيت وتليجرام كما هما → وصل يسحب الطلبات الجديدة من Apps Script بطلبات موقعة، حسب جدول الخادم الذي تختاره أو عند الطلب. لا تتغير عناوين إرسال اللاندنج أو تفاصيل البوت. رقم الطلب JS-… ثابت لمنع التكرار.

## Google Sheets وApps Script

1. أضف `WaslBridge.gs` إلى نفس مشروع Apps Script، وحدّث `Code.gs` في النشر الموجود؛ لا تنشئ رابط `/exec` مختلفًا.
2. شغّل `configureWaslReadOnlyBridge` من الشيت. يجهز مفتاح القراءة ويعرضه للمسؤول؛ لا يضيف أعمدة ولا يغير البوت أو رابط الأوردرات.
3. في وصل ← استيراد السجل القديم ← إعداد القراءة المباشرة، أدخل رابط النشر الحالي `/exec` والمفتاح. الخادم يتحقق من `ping` موقع قبل إظهار «متصل».
4. راجع معاينة الأوردرات القديمة ثم اعتمد الاستيراد، مع مراجعة العملة والأرقام والحالات غير السليمة.
5. اختار سحب الطلبات الجديدة تلقائيًا كل 1–168 ساعة، أو «اسحب الجديد الآن». رقم الطلب يمنع التكرار. لا يُكتب فوق الحالات الموجودة في وصل؛ تغييرات الحالات في الشيت تحتاج مراجعة مستقلة. الصفوف القديمة أو التي بلا تاريخ لا تدخل تلقائيًا كطلبات جديدة.

`configureWaslBridge` اسم قديم يستدعي إعداد القراءة فقط أيضًا. يبقى `BOT_TOKEN` و`ADMIN_CHAT_ID` في Script Properties دون تعديل. المزامنة من وصل إلى الشيت غير مفعلة؛ طلبات الكتابة مرفوضة افتراضيًا.

## واتساب

المجلد `whatsapp` إضافة Manifest V3. تثبيتها يتطلب إجراء من صاحب المتصفح. بعد نشر وصل، ينشئ المسؤول رمز اقتران مقيدًا بقراءة Paid؛ تحفظ الإضافة الرمز محليًا وتطلب إذنًا لرابط بوابة الأجهزة المحدد فقط.

القراءة تتطلب تسجيل الدخول إلى WhatsApp Web واختيار Paid. الأداة تجمع أرقام عناوين الصفوف، وتتوقف إن تغير التصنيف، وتحتفظ بالأسماء غير القابلة للمطابقة للمراجعة دون تخمين. لا ترسل رسائل واتساب. القراءة الدورية تعمل فقط مع المتصفح وتبويب واتساب مفتوحين. DOM واتساب غير ثابت؛ يجب اختبار القارئ على الحساب الحقيقي وتعديل المحول إذا لزم.

## أندرويد

مصدر Java في `android`، وبناء اختبار APK عبر GitHub Actions. إصدار الاختبار موقّع بمفتاح debug مؤقت، وليس إصدار متجر إنتاجيًا. بعد البناء يلزم تثبيت المستخدم، ثم رمز اقتران مقيد بإشعارات البريد، ومنح Notification access. لا تطلب الأداة READ_SMS أو SEND_SMS، ولا تقرأ الوارد القديم.

تقبل إشعارات تطبيقات Google Messages وSamsung Messages وcom.android.mms التي يكون مرسلها EGYPT POST/البريد المصري وتحتوي كود بعيثة. أي تطبيق رسائل مختلف يحتاج إضافة اسم الحزمة بعد التحقق. الرسائل تحفظ محليًا حتى إيصال حفظ بأرقام الأحداث من الخادم. حد الانتظار 500؛ يظهر تنبيه حالة عند الوصول إليه. لا تسجل نصوص الرسائل أو رموز الاقتران في logs. التشغيل الدوري عبر JobScheduler قابل للتأخير بسبب البطارية والنظام.

## بروتوكول بوابة الأجهزة على Convex

انسخ رابط بوابة الأجهزة `https://…convex.site` من إعدادات وصل إلى الأداة. هذا عنوان API مستقل عن عنوان واجهة Macaly.

كل مسارات أجهزة الجمع تتطلب `Authorization: Bearer <device token>`؛ قاعدة البيانات تحفظ hash الرمز فقط، مع owner وscope ووقت انتهاء وإلغاء. لا تمنح هذه الرموز صلاحية مشاهدة أو تعديل كل طلبات الحساب.

- `GET /api/integrations/devices/health`: `{ok:true,scope:"paid"|"postal"}` بعد التحقق من الاقتران.
- `POST /api/integrations/devices/paid`: `eventId, phones, unresolved, loaded, complete, observedAt, source`. يضيف دفعة مراجعة؛ يطبق تلقائيًا فقط إذا فعّل المالك ذلك، وكان التصنيف مؤكدًا والمطابقة وحيدة. الإقرار `{ok:true,applied:number}`.
- `POST /api/integrations/devices/postal`: `events:[{eventId,sender,text,receivedAt}]`. يحلل كل رسالة على حدة، ويحفظها بصورة idempotent؛ يرد `{ok:true,acknowledged:[eventId]}` بعد commit فقط.
- `GET /api/integrations/devices/alerts?cursor=…`: `{ok:true,alerts:[{id,title,body}],cursor,hasMore}` خاص بصاحب رمز أندرويد.
- مزامنة الشيت الحالية تعمل بالسحب من Convex إلى Apps Script؛ لا توجد بوابة استقبال Sheet webhook منشورة.

الظرف: `action:"wasl", ts:unixSeconds, nonce:random32hex, operation:"ping"|"snapshot"|"update", payload:JSON-string, signature:hex(HMAC-SHA256(secret,ts+"\n"+nonce+"\n"+operation+"\n"+payload))`. ارفض التوقيع الخاطئ والفارق الزمني أكبر من 5 دقائق وإعادة استخدام nonce. عند سحب snapshot، يستورد وصل الطلبات الجديدة فقط بواسطة رقم الطلب داخل حساب المصدر، دون اختلاق تواريخ للحالات القديمة أو تحويل عملة غير الجنيه ضمنيًا. التعديل من وصل إلى Apps Script يتطلب sourceVersion لمنع الكتابة فوق تعديل أحدث في الشيت أو تليجرام.

## التتبع والجدولة

رابط التتبع الرسمي الحالي: https://egyptpost.gov.eg/ar-eg//Home/EServices/Track-And-Trace . تعطل الاختبار سابقًا عند التحقق الأمني؛ لا يوجد parser مؤكد لحالات التتبع حتى إتمام بحث حي. لا تُعرض خدمة التتبع التلقائي على أنها تعمل. نقل الاستضافة لا يزيل التحقق الأمني ولا يمنح إذن إشعارات أندرويد.

تبقى اختبارات التشغيل الفعلية: موافقة Macaly ونشر الخادم، تحديث نشر Apps Script، تجربة الطلب في الوجهات الثلاث، واتساب حقيقي، تثبيت أندرويد وإذن الإشعارات، ثم موقع البريد. لكل ميزة وقت آخر نجاح وخطأ وحالة جاهزية منفصلة. الإعداد «كل X ساعات» لا يصبح فعالًا إلا بعد توصيل المنفذ الذي سيشغله.


إعداد القراءة يضبط WASL_ALLOW_UPDATES=0. طلبات update الموقعة تُرفض افتراضيًا قبل أي تعديل، والكتابة تحتاج تفعيلًا منفصلًا صريحًا من المسؤول.
